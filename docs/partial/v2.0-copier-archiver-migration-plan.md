# v2.0 Schema Migration: Copier + Archiver Fixes + Table Rename

**Status**: Planning
**Date**: 2025-11-16
**Scope**: Combined migration for schema v2.0 fixes AND `medium` → `media` table rename

## Objectives

1. **Fix broken tools**: Update ntt-copier and ntt-archiver for unpartitioned v2.0 schema
2. **Rename for consistency**: `medium` → `media` to match `paths` and `blobs` (plural naming)
3. **Minimize disruption**: Batch changes to avoid multiple migration cycles

## Background

### Current State
- **Database**: Unpartitioned v2.0 schema (post-partition elimination, Nov 2025)
- **Tables**: `medium` (singular), `paths`, `blobs`
- **Broken tools**:
  - `ntt-copier.py`: 18 refs to `inode` table, 6 refs to `path` table (both removed in v2.0)
  - `ntt-archiver`: 1 ref to `inode` table
- **Total `medium` refs**: 302 across 100+ files

### Schema Changes (v1.5 → v2.0)
- **Removed**: `inode` and `path` tables (separate tables)
- **Added**: `paths` table (denormalized, combines inode + path data)
- **Removed**: `inode.id` auto-increment column (was used for work claiming)
- **Impact**: Work claiming strategy needs redesign

## Migration Strategy

### Phase 1: Core Pipeline Tools (CRITICAL - BLOCKS OPERATIONS)

**1.1 ntt-copier.py** (bin/ntt-copier.py)

Schema mapping:
```
OLD (v1.5)                    NEW (v2.0)
---------------------------------------------------------
inode.id                   → paths.ino (composite key with dev)
inode.medium_hash          → paths.medium_hash
inode.ino, dev, size, ...  → paths.ino, dev, size, ... (same columns)
inode.copied               → paths.copied
inode.blobid               → paths.blobid
path.path                  → paths.path (merged into single table)
medium                     → media (table rename)
```

Key changes needed:
- **Line 245**: `SELECT MAX(id) FROM inode` → Remove (id column doesn't exist)
- **Lines 337, 348**: `FROM medium` → `FROM media`
- **Line 408**: `UPDATE inode SET copied = true` → `UPDATE paths SET copied = true`
- **Lines 458-485**: Work claiming queries (`UPDATE inode WHERE id IN (...)`) → **REDESIGN NEEDED**
- **Lines 520-555**: Work claiming WITH CTEs → Use `(medium_hash, ino, dev)` instead of `id`
- **Line 688**: `FROM path` → `FROM paths`
- **Line 942**: `UPDATE path SET blobid` → `UPDATE paths SET blobid`
- **Line 955**: `UPDATE inode SET copied = true` → `UPDATE paths SET copied = true`
- **Line 983**: `UPDATE inode SET status` → `UPDATE paths SET status`

**Critical redesign**: Work claiming strategy
```sql
-- OLD (used inode.id for atomic claiming):
UPDATE inode SET claimed_by = %s WHERE id IN (SELECT id FROM inode ... LIMIT 100)

-- NEW (use composite key):
UPDATE paths SET claimed_by = %s
WHERE (medium_hash, ino, dev) IN (
    SELECT medium_hash, ino, dev FROM paths ... LIMIT 100 FOR UPDATE SKIP LOCKED
)
```

**1.2 ntt-archiver** (bin/ntt-archiver)

Changes needed:
- **Line 240**: `FROM inode WHERE medium_hash = '$MEDIUM_HASH'` → `FROM paths WHERE medium_hash = '$MEDIUM_HASH'`
- **All `medium` refs** → `media`

**1.3 ntt-orchestrator** (bin/ntt-orchestrator)

Changes needed:
- **All SQL queries**: `medium` → `media` (18 occurrences)
- No `inode`/`path` table references (already uses `medium` table only)

### Phase 4: Database Rename (ONE-TIME OPERATION)

```sql
BEGIN;

-- Step 1: Rename table (FK constraints auto-update)
ALTER TABLE medium RENAME TO media;

-- Step 2: Verify FK constraint updated
\d paths
-- Should show: REFERENCES media(medium_hash) ON DELETE CASCADE

-- Step 3: Test basic operations
SELECT COUNT(*) FROM media;
SELECT COUNT(*) FROM paths WHERE medium_hash IN (SELECT medium_hash FROM media LIMIT 1);

COMMIT;
```

**Safety checks**:
- Verify no active copier/archiver workers running
- Take database backup before ALTER TABLE
- Test FK cascade with DELETE (on test data)

## Execution Order

1. **Fix ntt-copier.py** (most complex, work claiming redesign)
2. **Fix ntt-archiver** (simple, 1 query change)
3. **Update ntt-orchestrator** (18 table renames)
4. **Update support tools** (10 scripts, ~30 refs total)
5. **Execute database rename** (ALTER TABLE medium → media)
6. **Update sql/00-schema.sql** (canonical schema)
7. **Test end-to-end** (enum → load → copy → archive)
8. **Defer docs** (or update incrementally)

## Testing Plan

**Unit tests** (per-tool):
- ntt-copier.py: Verify work claiming with composite key
- ntt-archiver: Verify safety checks query correct table
- ntt-orchestrator: Verify workflow state tracking

**Integration test**:
1. Load test medium with ntt-loader
2. Run ntt-copier.py --medium-hash <test_hash> --limit 100
3. Verify paths table updated (copied=true, blobid set)
4. Run ntt-archiver for test medium
5. Verify archive creation and cold storage move

**Rollback plan**:
- Database: `ALTER TABLE media RENAME TO medium;` (reverses rename)
- Code: Git revert to pre-migration commit

| Documentation | NONE | Deferred, no functional impact |
